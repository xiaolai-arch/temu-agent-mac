# 2026-10-18 采集链路全面测试：链接采集/整店采集/1688 关键词采集

## 背景
插件逐商品点击路线词池饱和后净增率暴跌（旧词 2.5%），全面测试 ERP「产品采集」页的
7 种采集方式（链接/1688跨境热卖/导入/关键词/整店/插件/店铺互采），寻找批量通道。

## 结论速览
| 路线 | 速卖通 | 国内站(1688等) |
|---|---|---|
| 链接采集 | 接受URL但服务端抓不动，只能当查重器 | 未测（应为主场） |
| 整店采集 | ✗ 按钮不启用 | 未测 |
| 关键词采集 | ✗（无此功能，平台全是国内站） | 面板可用，极速采集点击无响应（待人工验证） |
| 插件采集 | ✓ 唯一可靠通道 | 插件支持部分国内站 |

## 关键发现

### 1. 链接采集（fetchType=linkCopy）
- 入口：产品 → 产品采集 → 链接采集；支持 URL/产品ID 一行一个，`$$`/`||` 可带自定义标题
- 底部「自动认领(发布)到平台」勾选时按钮为「采集并自动认领」，取消后变「开始采集」（测试请保持取消）
- 提交后弹「已提交采集任务」→ 结果进【公用采集箱】（erp.91miaoshou.com/common_collect_box/items）
  ——注意不是 Temu全托管采集箱，新箱在「未认领」标签

### 2. AliExpress 链接采集的真相（重要）
- 提交 `aliexpress.com/item/{id}.html` 服务端**抓不到数据**，失败原因：
  「采集失败 建议采集1688产品 或使用插件采集」
- 商品页对纯 HTTP 只回 77KB JS 壳（搜索页却有 795KB 服务端渲染），ERP 抓取器同样过不去
- 「跳过采集-产品已经采集过」的记录带完整价格/库存，**是拿箱内已有记录比对的，不是新抓**
- ⚠ 采集失败列表里 207+ 条多为「已采集过」跳过，不是真失败；失败数据仅保留 30 天
- **结论：速卖通采集唯一可靠通道 = 浏览器插件**，链接采集只能当查重器

### 3. 批量拿链接技术（可复用）
- `requests` 直拉 `aliexpress.com/w/wholesale-{kw}.html` 200 OK（795KB），每页约 60 商品
- 卡片 href 的 `utparam-url` 参数含规范 ID：`x_object_id:1005...`（3256 新式 ID 在路径里，
  1005 旧式 ID 在参数里；同一商品双 ID 形态）
- 提取脚本：正则 `x_object_id%3A(1005\d+)`（unquote 后）→ 拼 `item/{1005id}.html`
- UIA 树可读 156 个链接标题但无 href；剪贴板批量粘贴用 PowerShell Set-Clipboard 最稳

### 4. 整店采集（fetchType=shopCopy）
- 输入店铺首页链接 → 获取产品；速卖通店铺 URL 无任何反应（支持平台列表全是国内站）
- 未测国内店铺

### 5. 1688 关键词采集（fetchType=website）→ 待人工验证
- 平台可选 1688（图标点击成功）、关键词「餐巾纸」添加成功（显示未采集）
- 「极速采集」按钮：人工坐标/OCR定位/UIA find_and_click 三种方式点击均无响应，
  采集记录（30天）为空 = 任务从未启动；可能有前置条件（行勾选/弹窗/权限）
- **待人工**：手动点一次极速采集看反应；跑通后结果应进公用采集箱或右侧产品面板
- 面板自带供应链筛选：一件代发/包邮/24小时发货/1688严选/认证工厂等，采集条数默认20
