## 模式定案

多店铺 = **同一浏览器内切换登录账号**（每店一个手机号+密码）。
账号：main=hpoiZee(151…)、store-b=boliooZ(134…)、store-c=lecoddebujbrjq(152…，首登自动学习)。
**执行入口**：`python driver/switch_store.py <store-id>`（确定性脚本，不依赖 agent）。
2026-10-13 实测：main→b→c→main→… 五连切全部成功，每店 ~115-145s；
2026-10-16 UIA 链路实测（151 登录切回 EXIT=0/191s，含登录 57s）：每店 ~150-190s。

## 完整链路（2026-10-13 早定稿，全程程序可操作 ✅）

### 1. seller 登录（全自动，~45s）

干净 `/login`（已登录也直接出登录页）→ 「手机号登录」tab →
手机号框 `^a` 重打 → **点手机号框→Tab→`^a`→密码**（Tab 法，密码框无法坐标点击）
→ 「登录」按钮（OCR 定位）→ **「同意并登录」确认层**（点登录后弹出）→ 完成。
登录成功后常弹 **Edge「保存密码？」气泡**（盖住页面右侧，干扰 OCR/点击）→ 点「以后再说」关掉。

### 2. Agent Center 联动（授权链路 = 用户正常流程的程序化）

seller 与 agentseller **会话独立**；**切店身份切换唯一有效入口 = 卖家主页侧边栏
「定制商品内容」**（href 自带店铺上下文）。2026-10-16 定稿：侧边栏用 **UIA Hyperlink
Invoke**（`link_agent_center_ui`，像素点侧边栏历史上 ×18 无响应；Invoke 失败退真实
坐标点击），弹层用「授权卡 UIA 快扫 → OCR 分类」混合循环。**授权门/redirectUrl 直航
或弹窗授权只刷新授权、绝不切身份**——确认后仍是旧店且永不弹「确认切换」（11:3x 反复
实测），故门直航已从主链路移除（`pass_auth_gate` 仅用于登录落地场景自动过关）。

```
seller 主页 site-main
  → 侧边栏「商品管理」展开（「定制商品内容」子项在 (41,1203) 一带）
  → 点「定制商品内容」→ 页面弹授权卡：
      「即将前往 SellerCentral（全球）的「X」店铺」
      + 协议勾选行（勾选框在行首左侧 ~28px）
      + 「确认授权并前往」按钮（深色文字，OCR 可读）
  → 勾协议 → 点「确认授权并前往」
  →（Agent Center 挂着别店时）「确认切换」弹窗：
      「SellerCentral 当前已有登录中的店铺，确认切换吗」（当前 X → 即将切换为 Y）
      确认按钮 = 白字蓝底（OCR 读不出文字！）→ 用「不切换」行定位 + 像素级蓝色块检测点其左侧
  → 定制商品内容页打开（新标签）→ 账号 + 双按钮验证
```

### 3. 店名验证（防跑错店 = 最高风险控制）

- **主源**：seller 主页右上角账号名（大字，OCR 稳定）；授权卡标题「即将前往…的「X」店铺」兜底
- OCR 混淆归一化：№→li（boliooZ 常被读成 bo№oZ）、I/1→l、0→o，再比对
- 定制商品页右上角账号名**小字时好时坏** → 裁剪放大重读 + 链路捕获名兜底
- 未知店首登：读到**别家已知店名**也必须走联动（防假阳性跑错店）；成功后自动把店名
  写进 local.config.json `accounts.<id>.name`（下次严格校验）

### 登录手机号真根因（2026-10-22 定案，推翻 10-21「丢键」误判）

铁证：OCR 全图扫描读到框内值 **`861341996663`**（12 位 = 预填「86」+ 追加的号），
分步实测 `^a` 全选后框内值不变 → 全选无效；点击后截图显示**地区下拉被打开**
（中国大陆 +86 / 中国香港 +852）。两个独立根因叠加：

| 根因 | 证据 | 修复 |
|---|---|---|
| **点击落在 +86 国家码下拉上** | UIA 里 `name.startswith("+86")` 的 Edit 元素是**国家码选择器**（rect 即下拉框），点中心弹地区选择器；OCR「+86」文本中心 +132px 才是真实输入框（实测 (1893,638)） | `_phone_click_pos()` 用 OCR 定位，不再用 UIA 那个 Edit 的 rect |
| **`^a` 全选在此输入框无效** | 全选后值不变，输入被**追加**到预填「86」后 → 12 位非法 | `_clear_input()`：`END` + 连续 24 次退格（实测清空后 OCR 读到占位符「请输入手机号」）；密码框（同样有自动填充点）一并同修 |

**教训**：`^a` 不是万能的——某些站点输入框（尤其配合自动填充/受控组件）全选无效，
必须**回读实际值**验证，而不是假设选中了。UIA 元素名以「+86」开头 ≠ 手机号输入框。

## 新店接入 SOP（加第 4+ 家店铺，免改任何代码）

1. `local.config.json` 的 `accounts` 里加一项：`"store-d": {"phone": "15x…", "password": "…"}`
   （手机号+密码即可；`name` 留空，首登成功后脚本自动学习写回）
2. `python driver/switch_store.py --doctor` —— 环境自检（OCR 管线/窗口/新店凭据/同步插件）全绿再继续
3. `python driver/switch_store.py store-d` —— 首切：自动登录→联动授权→学习店名→严格验证
4. `python driver/switch_store.py --verify-all` —— 全店轮回实测（含新店），矩阵全 ✅ 即接入完成
5. 工作台（temu-panel）店铺卡片从 local.config.json 动态生成，重启工作台即出现新店按钮

原理：新店首登时 expected=None，脚本读到**别家已知店名也强制走联动**（防跑错店）；
成功后 `_learn_name` 把店名写进配置，此后与老店完全同权（严格校验+免登录直达）。
