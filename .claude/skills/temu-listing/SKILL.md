# temu-listing — Agent 实时接管上新

## 定位

**不是一键脚本。** Agent 实时驾驶 ego 浏览器，按「观察 → 推理 → 填写 → 验证 → 留痕」
逐段完成商品发布表单；推理字段自己填、自己验、不逐项问用户。

脚本只做确定性准备：切店、同步体检、主图裂变、建议价读取、导出。表单里的每个判断
（名称、属性、规格、价格、工艺、报关类型）都由 agent 现场推理。

## 每次运行前

1. **读 ego 指南**：`ego-browser skill`（版本变化后必读）。
2. **切店 + 体检**：`run switch-store <store>`，再 `run sync-check <store>`，确认
   账号名、登录态、插件双按钮正常。
3. **生图**：`run fission <首图>` → 默认 5 张 1K。原始首图不排轮播第一张；
   从生成图里随机挑一张作主图。
4. **建议价**：读 `modules/grind/data/suggested-prices.csv`（按 SKC/类目匹配；
   无匹配时用同类在售商品中位价）。
5. **固定 TaskSpace**：`temu-agent`，p1 = 卖家后台。所有动作序列尽量在同一脚本轮内完成。
6. 若报 `Control of this task space is with the user`：**硬停**，请用户点「交还给 Agent」
   或回复“继续”，绝不重试、绝不抢控制权。

在 ego 脚本里加载原子操作：

```js
const c = await import("file:///Users/Admin/PycharmProjects/temu-agent-mac/lib/common.mjs");
const h = await import("file:///Users/Admin/PycharmProjects/temu-agent-mac/modules/listing/helpers.mjs");
const { task, page } = await c.boot();   // 复用固定 TaskSpace（p1）
```

## 推理规则（核心）

### 1. 类目

- 用商品名词搜索（如“派对餐巾”），选**最具体的叶子类目**，核对结果全路径。
- `text=` 匹配不到类目结果，要点结果行的**全路径 div**。

### 2. 中英文名称

- 两个字段各 ≤250 字符（以页面计数器为准）。
- 结构：`[风格/主题] + [品类] + [材质/工艺] + [功能卖点] + [定制说明] + [使用场景] + [规格]`。
- **原创改写，不照抄竞品标题**；不堆砌无关关键词。
- 禁用绝对化用语（最/第一/100%/永久）、未授权品牌词、无法证明的认证。
- 定制商品必须写明「可定制姓名/文字/图案」；多规格写明数量档位。
- 英文名按英语习惯写，不做逐字直译。

### 3. 商品属性

- 只填能从实物/图片/描述确认的项；**没有如实选项就留空，并在日志写明原因**，绝不虚构。
- 节假日等多选字段只选相关项；误加的标签用 tag 关闭图标删除。
- 品牌名只能从平台品牌库选；无品牌/无商标资质就留空。
- 成分遇到“只有纺织纤维、没有纸”这类情况，留空（错填属于虚假申报）。
- 填完看「属性填写率」，记录分数和缺项原因。

### 4. 规格与数量档位

- 平台没有「尺寸」父规格时用**尺码**（如 `23cm×23cm`）。
- 数量值必须带平台接受的单位（`pcs/set`），`sheets/set` 这类会被判空。
- 档位按使用场景/物流成本/价格带选 3~4 档；参考同类在售 SKU。
- SKU 表未生成 = 规格值没提交成功；用真实键盘重填，不要改代码硬塞。

### 5. 价格

- 申报价 = 建议价 × **1.5~2.0**；无建议价时用同类中位价。
- 档位间保持合理阶梯（数量越多单价越低）；尾数可用 .9。
- 建议零售价高于申报价，货币按店铺站点选（本次 CNY）。
- 所有价格填入后逐行复核，防止行错位。

### 6. 包装、体积、重量

- 按 SKU 数量估算：数量越多，箱规/重量递增；同 SKU 内保持单调。
- 体积/重量是估算值，日志里明确标注“需实物复核”。
- 包装图必须含商品/类目信息；只有通用无标签纸箱时，主动提示仓库拒收风险。

### 7. 定制工艺

- 客户可改文字 → 丝网印刷-文字；客户可传图案 → 丝网印刷-图片；两者都有 → **组合工艺**。
- 组合工艺的二级工艺是**多选、至少 2 项、不能重复**；切换单一/组合会清空已选，一次选好。
- 一级工艺按品类选（纸/画布类 = 画布/纸张定制工艺）。

### 8. 报关类型

- 创建时弹「平台报关需根据商品所属类型确定关税」，按商品实质选最准确项。
- 餐巾/派对餐巾 → **餐巾**；不确定时选「都不是，自定义」并如实描述，不硬套。

### 9. 图片

- 轮播：生成图 5 张；原始主图**不排第一**，随机生成图作主图；尺寸图最后。
- **数量/尺寸标识禁用**：源首图若带数量标识（50 PCS/100 张等）或尺寸标注，**不用于
  裂变**，另选干净图；裂变提示词与全部链接图片均不得出现数量、尺寸文字
  （2026-11-08 用户明确）。
- SKU 预览图用干净白底产品图（如 `04-white`）；素材中心按名称搜索后选唯一卡片。
- 删错图要派发完整 pointer 事件序列；不要只 click。

### 10. 异常判断

- 先读页面可见错误/弹窗，再决定动作；**不盲点、不盲重试**。
- 校验红字定位到具体字段，先修根因再提交。
- 验证码/滑块/拼图出现 → 立即停手报告，绝不自动求解。
- 页面跳转/弹窗遮挡：先快照确认当前状态，再继续。

## 页面流程

### 0. 新建商品

- 商品管理 → 新建商品 → 类目搜索 → 点全路径 div → 下一步。
- 落地：`https://agentseller.temu.com/goods/edit?productDraftId=...`。

### 1. 基础信息

- 中文名 / 英文名：按「推理规则 2」写入，计数器核对长度。
- 商品产地：国家 中国大陆 + 省份（下拉可能掉，重选国家后再选省份）。
- 制造地点：中国大陆。

### 2. 商品属性

- 按「推理规则 3」逐项填；多选用 tag，误选用 `h.closeTag`。
- 填完核对填写率，记录留空项与原因。

### 3. 规格与 SKU

- 父规格用尺码，值用 `h.setReactInput` 真实键盘输入（失焦/Enter 提交）。
- 数量档位逐行添加；SKU 表生成后再填价格。
- 申报价 / 建议零售价 / SKU 分类 / 预览图逐行设置，**每行都要复核**。
- 尺码合并单元格（rowspan）时，下面行少一个 td，取单元格按行判断。

### 4. 包装与物流

- 外包装图用隐藏 `input[type=file][multiple]` 一次上传。
- 敏感属性默认「是」→ 选「否」后逐 SKU 填体积/重量/净重。

### 5. 定制属性

- 选中「定制商品」→ 工艺类型 → 一级/二级工艺（按「推理规则 7」）。
- 平台提示创建后还需维护「定制模版内容」，记住这个后置步骤。

### 6. 保存草稿

- 保存成功信号：弹窗「保存成功 提交商品信息且创建成功后方可生效」。
- **必须点「确认」关掉**，否则挡住后续点击。
- 保存前读一遍 `h.visibleErrors`，有红字先修。

### 7. 创建 / 发布

- 点「创建」→ 报关类型弹窗 → 按「推理规则 8」选择 → 确认。
- 成功弹窗「定制商品创建成功」→「立即维护」跳转商品列表并打开
  「修改定制信息」抽屉（步骤：① 配置定制信息 → ② 填写库存）。
- 记录 SPU / SKC / 当前状态（常见：未发布到站点）。

### 8. 定制信息 + 库存（按用户意愿）

- 配置定制信息需要：背景图（宽高 800~2000px、<3M，**不能带示例文字**）、
  定制区域（图片/文字、起点 X/Y、尺寸 宽/高、最小像素要求、是否必须上传）、
  可选蒙版图（PNG，800~2000px、<5M）。
- 用户说“先不做”就跳过，不要擅自上传底图或保存区域配置。
- 后续补：商品列表该行 →「填写定制信息」→ 保存并下一步 → 填写库存。

## 验证与留痕

每个区块完成后：

1. 读 `h.visibleErrors(page)`，有红字先修。
2. 用 `page.evaluate` / snapshot 复核关键值（名称长度、填写率、SKU 行数、价格）。
3. 关键节点截图（`c.shot(page, "listing-...")`）。
4. 写决策日志到 `logs/listing-<日期>-<SPU或draftId>.md`：

```md
## [区块] 基础信息
- 观察：...
- 推理：为什么这样命名/选这个属性/定这个价
- 填写：实际填入值
- 验证：页面回读结果（计数器/填写率/行数）
- 待确认：留空项与原因
```

日志是给用户复盘用的，不是形式主义：每个推理字段都要能回答“为什么这么填”。

## 检查点与红线

- **推理字段自己填、自己确认**（2026-11-07 用户明确），不逐项打断用户。
- **写操作**：
  - 保存草稿：可按流程直接做，日志记录。
  - 创建/提交上架：用户当次明确说“发布/上架”= 授权；只说“填表/整理草稿”则不点创建。
  - 定制信息保存、库存提交、批量操作：需用户明确确认。
- **验证码永远人工**；出现即停手报告，不自动求解。
- **用户接管浏览器即硬停**，等用户交还后再继续。
- 不虚报属性/材质/认证；平台明确写了违规可下架/禁售。
- 凭据只在 `local.config.json`，日志/报告不打印密码/Token。

## 坑速查

| 症状 | 处理 |
|---|---|
| 规格输入框有值但 SKU 表不生成 | JS set value 无效；用 `h.setReactInput` 真实键盘输入 + 失焦/Enter |
| `element is not visible in the viewport` | 先 `scrollIntoView({block:"center"})` 再按坐标点（`h.findPoint` 已内置） |
| 插件浮层/待办弹窗挡点击 | 按钮走 `c.clickButton`；弹窗 X 用 `c.closeModals`（`MDL_iconWrapper` 在右上角外侧） |
| 保存成功弹窗挡住后续 | 必须点「确认」 |
| 类目搜索结果点不到 | 点结果行的全路径 div，不用 `text=` |
| 数量 `sheets/set` 被判空 | 换 `pcs/set` |
| 多选误加节日 | `h.closeTag` 删除标签 |
| SKU 行单元格错位 | 尺码 rowspan 合并，下面行少一个 td |
| 定制二级工艺选不了重复项 | 平台去重，必须选至少 2 个不同项 |
| 省份下拉掉/“不能为空” | 重选国家后再选省份 |
| 页面提示 “Base Property Value Cannot Be Empty” | 先读可见红字定位字段，常见是空的成分/属性行 |
